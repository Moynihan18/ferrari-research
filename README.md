# Sales Research Dashboard

A weekly-refreshed research dashboard tracking 87 AI model labs and competitor
inference customers, sourced from the "Model Labs / Competitor Inference
Customers" account list. For each account it surfaces recent news (acquisitions,
funding, leadership changes, product launches, partnerships) with a sales-relevance
note, live Reo.dev account activity, and a precomputed weekly outreach plan with
draft messages for the accounts most worth contacting.

## How it works

```
data/companies.json       - the 87-account list (name, domain, CEO, valuation, SF status, ...)
data/news.json             - recent news per account, classified + summarized
data/reo_activity.json     - Reo.dev engagement signal per account
data/outreach_plan.json    - ranked weekly outreach targets with draft messages

index.html + assets/       - static dashboard that reads the data/*.json files

scripts/fetch-reo-activity.js    - pulls live Reo.dev signals via the public REST API
scripts/fetch-news.js             - researches recent news per account (Cursor CLI agent + its web search)
scripts/generate-outreach-plan.js - ranks accounts and drafts outreach messages (Claude)
scripts/build.js                  - runs the three steps above in order

.github/workflows/weekly-refresh.yml - runs the pipeline every Monday and publishes
                                         the dashboard to GitHub Pages
```

The dashboard itself is a static site (no backend) so the "Outreach Plan" button
just displays whatever `data/outreach_plan.json` was last generated by the Monday
refresh — it is not calling an LLM live in the browser.

## Viewing it locally

```bash
npm install
npm run serve
# open http://localhost:8080
```

## Setting up the weekly automation

The GitHub Action (`.github/workflows/weekly-refresh.yml`) runs every Monday at
12:00 UTC, installs the Cursor CLI, refreshes `data/*.json`, commits the
result, and publishes the dashboard to GitHub Pages. It needs four repo
secrets configured under **Settings → Secrets and variables → Actions**:

| Secret | Used for | How to get it |
| --- | --- | --- |
| `CURSOR_API_KEY` | News research (`fetch-news.js`), via the headless Cursor CLI agent's own web search tool | Cursor dashboard → API keys |
| `ANTHROPIC_API_KEY` | Outreach plan generation (`generate-outreach-plan.js`) via the Claude API | [console.anthropic.com](https://console.anthropic.com) → API keys |
| `REO_API_KEY` | Live Reo.dev account activity (`fetch-reo-activity.js`) | Reo dashboard → Settings → Configurations → API Keys → "Product Export & Zapier Integration" → copy the Data-out key (admin role required) |
| `REO_SEGMENT_ID` | Resolving each account's domain to a Reo `account_id` | Create (or reuse) a Reo segment/list that contains these 87 accounts, then copy its segment ID from the Reo UI |

You'll also need to enable GitHub Pages for this repo: **Settings → Pages →
Source: GitHub Actions**.

Without these secrets, `fetch-reo-activity.js` writes an empty result rather
than failing the whole run, but `fetch-news.js` requires `CURSOR_API_KEY` and
`generate-outreach-plan.js` requires `ANTHROPIC_API_KEY` to do anything useful.

**Unresolved risk with `fetch-news.js`:** there's a community report (Cursor
forum, Nov 2025) that the Cursor CLI agent lost access to its `web_search`
tool in headless/print mode. This repo can't verify that from CI. Watch the
first few runs' `data/news.json` — if items start showing up with no real
`url`/`source` (or the batch results look invented rather than found), the
CLI isn't actually searching and `fetch-news.js` needs to move back to an
API with a guaranteed web-search tool (it was previously implemented against
the Claude API with `web_search_20260209` — see git history — which is a
known-working fallback).

### Running the refresh manually

```bash
# fetch-news.js needs the Cursor CLI installed and on PATH:
curl https://cursor.com/install -fsS | bash

export CURSOR_API_KEY=...
export ANTHROPIC_API_KEY=...
export REO_API_KEY=...
export REO_SEGMENT_ID=...
npm run refresh
```

Or trigger the GitHub Action manually via **Actions → Weekly research refresh →
Run workflow**.

## Known limitations of the current data

- **Initial data (this commit)** was researched manually in a single pass —
  live web search plus direct Reo.dev account-research calls — rather than by
  the automated pipeline above. It reflects the state of each account as of
  **2026-07-21**.
- **LinkedIn**: there is no LinkedIn API for company-post search, so news
  research relies on general web search (which surfaces LinkedIn posts that are
  indexed by search engines) rather than the LinkedIn API directly.
- **Reo.dev's public REST API** (`https://developers.reo.dev`) exposes raw
  activity events and segment/account listings, not the richer computed
  engagement scoring available inside the Reo product itself. `fetch-reo-activity.js`
  approximates that scoring (event counts, last-seen date, distinct developers)
  from the raw feed — it will not be byte-identical to what you see in the Reo UI.
- **Company list**: to add, remove, or edit accounts, edit `scripts/seed-companies.js`
  and re-run `npm run seed` (this rewrites `data/companies.json` from scratch, so
  don't hand-edit that file directly).
